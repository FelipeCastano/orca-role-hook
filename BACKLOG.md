## Ideas

- **Run one check or one group of checks of a smoke section.** A section is one function whose checks depend on fixtures, fakes and result strings defined earlier in it, and a check has no name to select; it needs a name per group, each group's fixture prefix and an explicit reset at its start. Today the unit is the section (`tests/smoke.sh <section>`).

- **Tabs Orca resumes by itself lack the kit's shim in their PATH** until `roles` reopens them.
- **Windows-side processes of an `orca` call the kit killed at its time limit** (WSL). Whether any stays running is not verified.
- **Cost figures from Orca's cost state** are 12-22 % above the sums of the transcripts, and unknown after `--resume`; find out which is right before relying on them.
- **The oracle's spec file is writable by workers.** The Planner saves each Dev spec under its scratch folder in `~/.orca-roles/tmp/`, which workers may write (only the kit's own files are protected, and Edit-only for Claude); a Dev could change the acceptance command before the oracle reads it. Keep the spec outside workers' reach or check its hash against the dispatched task's spec.
- **Test the OpenCode pass's state drop and deadline** (usage_metrics). PR8 set audit, low: opencode_sessions drops from state.json the ids no longer in OpenCode's store and stops at the pass deadline, but no smoke check covers either (a mutant that removes the drop passes usage-metrics).
- **Narrow on-done.sh's Decisions matcher.** Its heading family matches any heading containing "decision" (for example a Dev report's "Implementation decisions" section), which printed 1.6–4.9k extra characters on 4 of 15 measured reports (coord-scripts measurement); anchor it to a `Decisions:` line or a heading titled exactly Decisions, and stop printing a pathless `worker_done` body twice (inbox.sh and on-done.sh both print it, +14–17 % on those handoffs). It changes the on-done output contract and its tests.
- **"An older Orca" next to delivery_id is inaccurate.** Orca 1.4.259's consuming `check` carries a `deliveryId` already acknowledged, and a second `--ack` returns a duplicate result with no error, so the parenthesis "(an older Orca)" beside `delivery_id` in the workers' common prompts, the peon prompt, `prompts/coordinator.md` and `bin/inbox.sh`'s header is wrong but harmless; reword the whole family at once (the coordinator.md sentence is pinned in sec_inbox).
- **The front role's Run lookups after an Orca restart.** kickoff.sh's front_mail (the Run whose coordinator_handle is the front role's) and its stale-Run check still use the front role's saved handle, while the messages to the front role now use its live handle. After a restart with a stale saved handle, the mail watcher can log "No Run is bound" although the Run was re-bound, and the stale-Run hint can name a Run that is bound to the live tab. Resolve both with the live handle kickoff already computes; it changes which Runs count as stale, so it needs its own design. Set audit of wsl-fixes-2, note N1.

Measure on the first real Tester round after the merge and reinstall: its wall time and the time and command count of those steps, against earlier rounds in `~/.cache/orca-roles/test-runs.jsonl` and the round timestamps; the base-side time is the `base-check` entries whose `worktree` field is the base copy, not the Tester's worktree (after the change each round also logs a `base-check` entry for the worktree run that `basecheck` adds, reported apart as its extra cost). Keep, tune or revert by that measure.
