# Local coordinator: new requests and scope changes
Read on demand from local-coordinator.md (same folder), which names the moment to read it. Everything in local-coordinator.md still applies.

## Latest base
Before the first Planner task of each new request (a new paper's `intake` task, or a `plan` task for a change the user asks for), run `~/.orca-roles/bin/sync-base.sh` once from the worktree, never while a code task is in flight, and only when no checkpoint is listed (`~/.orca-roles/bin/checkpoint.sh --list` prints nothing); otherwise tell the user in one line that the request is planned on the current base. Exit 0: go on, and tell the user its line only when it says "Fast-forwarded". Exit 3: tell the user in one line that the fetch failed and the work starts on the local copy, and go on. Exit 4: when no checkpoint is listed (`~/.orca-roles/bin/checkpoint.sh --list` prints nothing) and `git status --porcelain` prints nothing, ask the user, as a self-contained question with the script's line, whether to merge the remote base now (`git merge --no-edit origin/<base>`, a merge commit on the user's yes; on a conflict, `git merge --abort` and tell the user) or to continue on the current base, recommending the merge; otherwise (a checkpoint is listed or the tree has changes) tell the user in one line that the branch is behind the remote base and go on, without offering the merge. Exit 2: tell the user its message.

## Scope changes during a plan task
If the scope changes while a `plan` task runs, stop it at once instead of letting it finish a draft: settle its dispatch with `orca orchestration worker-abandon --dispatch <dispatch_id> --json`, then run `~/.orca-roles/bin/interrupt-role.sh planner` in the foreground with a Bash timeout of 600000 ms. Only when it says the Planner stopped, compact it (`~/.orca-roles/bin/compact-role.sh planner --instructions "<what to keep of the draft>"`) or, when nothing of the draft is worth keeping, clean it (`~/.orca-roles/bin/clean.sh planner`): a dispatch abandoned this way is not a task in flight. Read and acknowledge any late report of the abandoned dispatch (`~/.orca-roles/bin/inbox.sh --run <run_id>`), then send a new `plan` task with the new scope. If `interrupt-role.sh` exits non-zero, or the Planner does not run on claude, tell the user in one line and dispatch nothing to the Planner until its report arrives, `~/.orca-roles/bin/team-status.sh --run <run_id>` shows it `done` or `interrupted`, or the user tells you to go on.
