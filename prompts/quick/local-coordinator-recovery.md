# Local coordinator: recovering the team yourself
Read on demand from local-coordinator.md (same folder), which names the moment to read it. Everything in local-coordinator.md still applies.

  - **Recovering the team yourself.** If `dispatch.sh` (or any orchestration call) fails with `terminal_handle_stale`, or a worker's handle does not respond, do not retry with that handle and do not ask the user: (1) the check above, then read and acknowledge every message; (2) run `~/.orca-roles/bin/launch.sh --reopen` from the worktree, never with any other option (it reopens only the roles whose tab was lost; roles closed with close-role.sh stay closed); (3) end your turn and dispatch nothing until the kit tells you the result: the `status` "Roles reopened" messages (one per role) with the new handles and the roles it could not reach, until one has no "Still starting" list, or, if launch.sh said that you will be reopened, your startup message after the reopen (no message comes when launch.sh prints "All roles are already open." or that it cannot start your relauncher: then go on at once with step (4), using the handles launch.sh printed, and if no role was reopened, tell the user); (4) `orca orchestration worker-list --run <run_id> --json`: abandon the dispatches whose terminal is none of the current handles (`orca orchestration worker-abandon --dispatch <id> --json`) and re-dispatch, as retries, only the tasks that have no `worker_done`, with the worker's last message (or "no report") in the spec; (5) tell the user in one line which roles were reopened. Run `--reopen` at most once per role until the user says otherwise; a role still not live, or not reached, is reported to the user and gets no dispatch. If launch.sh says it cannot start your relauncher, tell the user in one line to run `roles` from another terminal of this worktree to give you back the kit's settings.
